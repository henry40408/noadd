Rust tests that were not ported one-to-one (Step 5), and why.

Page-miss tests (logs_page_miss_bench.rs, dashboard_page_miss_bench.rs,
stats_page_miss_bench.rs)
  Rust counted SQLite page misses with a tracking VFS to prove a query reads
  few pages. modernc.org/sqlite exposes no such hook. Replaced by EXPLAIN
  QUERY PLAN assertions (TestLogPagesUseIndexes): the page query must name
  idx_query_logs_timestamp, and the type-only page must name
  idx_query_logs_type_blocked_ts. TestStatsAgreeWithTableAcrossPrune pins the
  results of the rollup-backed readers against direct table counts, which is
  the other half of what the page-miss tests guarded.

Tracking-allocator / memstatus benches (stats_contention_bench.rs,
cache_memory_bench.rs)
  They measure rusqlite and the Rust allocator (SQLITE_CONFIG_MEMSTATUS).
  modernc.org/sqlite is a Go transpilation with no such switch. Go's own
  numbers are in bench_test.go (BenchmarkStatsSummary, BenchmarkQueryLogsPage,
  BenchmarkInsertBatch500; BENCH_DB and BENCH_NOW select the data).

Deviations from the Rust behaviour
  - ValidateDohToken, EarliestLogTimestamp and LatestLogTimestamp return the
    database error; Rust swallowed it with .ok().
  - Top query types with equal counts are ordered by name; Rust's order came
    from HashMap iteration and was not defined.
  - Rust tests that only exercised the rusqlite API (test_read_conn_opens...)
    are covered by db_test.go (reader is read-only, WAL visibility, pragmas).
